# eRISCV-M2 BSP Toolchain Contract

This is the M2 bare-metal build contract. A compatible build
must use the settings below; changing ISA, ABI, memory layout, or image format
creates a different BSP compatibility target.

| Item | Contract |
|---|---|
| Compiler prefix | `riscv64-unknown-elf-` |
| Compiler version | GCC 15.3.0, installed with `tools/toolchain/bootstrap_riscv_gcc15.sh` |
| ISA | `rv32imfc_zicsr_zifencei_zicntr_zihpm_zihintpause_zba_zbb_zbs_zicond_zcf` |
| Bare-metal ABI | `ilp32f` |
| RTOS ABI | `ilp32` (`RTOS_ABI`; no FP task context) |
| Code model | `medany` |
| Runtime | freestanding; `-nostdlib -nostartfiles` |
| Linker script | `linker/eriscv_mcu.ld` |
| ITCM | 128 KiB at `0x1000_0000` |
| DTCM | 128 KiB at `0x1100_0000` |
| System SRAM | 512 KiB at `0x8000_0000`; opt-in `.system_sram` NOLOAD section |
| BSP boot address | `ERISCV_MCU_BOOT_ADDR` (`0x1000_0000`, ITCM base) |
| Images | `<example>.imem.mem`, `<example>.dmem.mem` generated by `tools/elf_to_mem.py` |
| Default regression simulator | Verilator |

## Reproducible commands

```bash
make -C eriscv-m2/sw images-all
make -C eriscv-m2/sw ci
make -C eriscv-m2/sw sim-fpu-fft
make -C eriscv-m2/sw sim-fpu-fft1024
make -C eriscv-m2/sw sim-fpu-fft1024-mcycle
make -C eriscv-m2/sw sim-coremark
```

The CI suite is `hello_uart`, `timer_apb_poll`, `timer_clint`, `wfi_tickless`,
`irq_timer_uart`, `wdt_smoke`, the four direct/descriptor DMA System SRAM examples,
`fpu_dma_sram`, `dma_uart_tx`, and the bit-exact 128-point RV32F `fpu_fft`.
`fpu_fft1024` is an on-demand extended stress test; `async_uart` remains an experimental example.

## Compatibility rules

- The authoritative compiler contract is `isa.mk`. Bare-metal targets expose
  overridable `ISA` and `ABI` variables; RTOS targets use `RTOS_ABI=ilp32`.
- Application objects must compile with the ISA and ABI above.
- Applications may use only the API in `include/eriscv_mcu.h` and addresses in
  `include/eriscv_mcu_config.h`.
- `ERISCV_MCU_BOOT_ADDR` and the linker `__eriscv_mcu_*` region symbols are the
  published BSP memory-map contract. Simulation runners take `boot_addr` from
  the linked ELF entry point; they do not carry a separate address setting.
- The simulator consumes the generated memory images, not an ELF directly.
- `ERISCV_MCU_SYSTEM_SRAM_BUFFER` places an uninitialized object in shared
  System SRAM. `.data`, `.bss`, `.noinit`, and stack remain in DTCM; startup
  does not initialize `.system_sram`.
- `eriscv_mcu_fp_enable()` must run before the first FP instruction because
  reset leaves `mstatus.FS` Off. The BSP exposes FCSR helpers in
  `include/eriscv_mcu.h`; it provides no C library or math library.
- FreeRTOS and Zephyr deliberately use `RTOS_ABI=ilp32` until their task
  context save/restore includes `f0`-`f31` and FCSR.
- The default trap path contains no FP code. Application trap hooks must not
  use FP until trap-entry context preservation covers FP registers and FCSR.
- Verilator is the default regression backend. Use ModelSim for focused
  debugging and waveform inspection; neither simulator replaces FPGA or board evidence.

The CoreMark smoke is a separate M2 benchmark target. It uses pinned CoreMark
v1.01, one validation iteration, and `mcycle`; its automatic backend prefers
Verilator and falls back to ModelSim. Its cycle result is not an official
CoreMark score because it does not satisfy the upstream 10-second reporting
rule.
